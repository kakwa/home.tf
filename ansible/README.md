# ansible-homelab

Ansible playbooks and roles for my homelab hosts.
Run from this directory (`ansible.cfg` sets the default inventory to the
`inventory/` directory and the role paths).

## Playbooks

| Playbook | Target | What it configures |
| --- | --- | --- |
| `hypervisor.yml` | hypervisor (`kvm.local`) | base system roles, serial console, Talos tooling, Proxmox VE, terraform sync |
| `ai.yml` | AI server (`ai.local`) | base system roles, llama-server (ROCm + nginx proxy), Wake-on-LAN and idle suspend |
| `utility.yml` | utility VM | base system roles, certbot, OpenLDAP, ldapcherry, Docker registry |
| `infra-dns.yml` | infra pool: DNS VM | base system roles, BIND (authoritative for `int.kakwalab.ovh` + TSIG dynamic updates, recursive resolver, adblock) |
| `infra-ldap.yml` | infra pool: LDAP VM | base system roles, OpenLDAP, ldapcherry (nginx, self-signed TLS), SSH-via-LDAP |
| `infra-ansible-master.yml` | infra pool: Ansible master VM | base system roles (Ansible control node), certbot with OVH DNS-01 for `int.kakwalab.ovh` + `*.int.kakwalab.ovh` |
| — | infra pool: registry VM (`infra_registry`) | provisioned by OpenTofu with a 200 GB boot disk (Docker registry data) |

## Inventory and static IPs

The inventory is the `inventory/` directory; Ansible merges every `*.yml`
file in it, one file per pool:

- `hypervisor.yml` — the hypervisor host (`kvm`) and its Proxmox pool
  configuration (`pve_pools`, consumed by the `proxmox_pools` role).
- `ai.yml` — the AI server (`ai`).
- `infra.yml` — generated by OpenTofu (`tofu/infra`); lists the infra pool
  VMs (`dns`, `ldap`, `ansible-master`, `registry`) in the `infra_dns`,
  `infra_ldap`, `infra_ansible_master` and `infra_registry` groups. Overwritten
  on every `tofu apply`, gitignored.

Each file holds the host's NIC configuration under `static_ip_nics`
(consumed by the `static_ip` role). The utility VM is intentionally absent
from this inventory: it is provisioned by Terraform and gets its network
config from cloud-init/netplan. Use
`ansible-playbook -i ../terraform/inventory.yml utility.yml` for that host.

## Bootstrap

`bootstrap.yml` is the single entry point for a new host. It:

1. Deploys the SSH public key, installs `sudo`, `python3`, `python3-apt` and
   `python3-debian`, and configures passwordless sudo. This part uses only
   `raw` tasks with fact gathering disabled, so it works on hosts with **no
   Python installed**. Elevation is auto-detected (passwordless sudo, falling
   back to `su`).
2. Once Python exists, runs the `static_ip` role to apply that host's NIC → IP
   mapping from `inventory.yml` (see the inventory section above). Hosts with
   no mapping are skipped.

Use the default inventory and `--limit` to target one host:

```bash
export HOSTNAME=192.168.1.227
export LOGIN=kakwa

ansible-playbook -k -K --limit kvm -e "ansible_host=$HOSTNAME" -e "ansible_user=$LOGIN" bootstrap.yml
```

## Configuration

To configuration the hosts:

```bash
# apply everywhere
ansible-playbook
# apply only on a specific host
ansible-playbook --limit kvm
# apply only a specific configuration
ansible-playbook --limit kvm --tags proxmos
```
